# Phase 3 — Supabase quota-bound private IPA intake registry

Live database migrations: `20261102231052 admin_ipa_intake_registry_quota` and `20261102231143 fix_admin_ipa_intake_quota_column_alias`.

The `ipa_upload_intakes` table stores only an Admin-owned receipt, original filename, expected file size, private `quarantine/<UUID>.ipa` object key, state, timestamps and placeholders for verifier metadata. RLS is enabled. `anon` has no table access; authenticated users have **SELECT only** for their own rows AND an Admin role. No browser or normal user may set `state`, `sha256_verified`, `signature_trusted`, or `install_eligible`.

Creating a reservation requires `public.reserve_ipa_intake(text,bigint)`, a `SECURITY INVOKER` wrapper around a **private-schema definer** with an explicit Admin database role + verified, unbanned Auth user check. It serializes reservations per account and enforces at most 5 requests/hour, 3 unexpired pending reservations, 500 MiB per 24h and 100 MiB/file. Returned private path is generated by database, not the browser.

`POST /api/admin/uploads/prepare` only requests a receipt and generates the actual R2 presigned URL after **all existing safety gates** are enabled (WAF, private lifecycle, trusted scanner, Admin Auth). This is **OFF** in Preview and Production. A server-signed URL and database receipt never imply that an IPA reached R2. There is no trust attestation, release permission or OTA installation. A service worker must later validate the R2 object size/content hash and independent Apple signatures, and move states through a controlled service-only transition.

`GET /api/admin/uploads/intakes` lists up to 20 RLS-filtered receipts for the authenticated Admin using a user JWT and publishable Supabase key; there is no secret-role key in the browser. The Admin Versions page displays this list with explicit `reserved` / `quarantined_unverified` labels.

Security hardening still required before enabling IPA upload:
- storage lifecycle deletion for orphaned objects, object status/size/hash reconciliation and reliable scanner queue; no orphan cleanup implemented here;
- device/profile verification; no code signature trust implemented here;
- durable quota audit, background expiration cleanup, malware scanning, server-only release approval, and Safari multipart for IPA over 100 MiB;
- real Preview integration tests with a trusted Admin JWT, CSRF, object byte-length checks, WAF/rate limits and malicious archive cases.

**Do not enable the real IPA upload feature flags to test the registry or UI.** The registry currently contains no real IPA; database tests used an explicit transaction with ROLLBACK.
